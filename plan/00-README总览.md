# 10-17-session-to-regression 项目计划总览

**项目**：会话 → 回归测试用例生成器（从本机 Claude Code / Codex 会话日志切出 bug-fix episode，把修复 diff 反推成可复跑的 pytest 骨架；纯本地 Python CLI）
**方法论**：数据先行 + 合成会话植入真值 + 确定性规则（零模型）+ RED/GREEN 双验证 + 数值口径一处定义 + 纯本地零上传
**项目系列**：同系列新题（**不参赛**，发布 GitHub **公开仓库**，署名 `yuluo554`）。**品牌隔离**：与同系列其他项目不共享代码、不互相提及业务领域；公开文档只描述本题问题域
**命名约定**：本地目录 `10-17-session-to-regression`（`10-17` = 2026-10-17 日期标签）；**GitHub 仓库名 = `session-to-regression`（纯净名）**，沿用惯例 `yuluo554/<kebab-name>`；LICENSE / pyproject 署名一致
**定位宣言（v1）**：**从 agent 会话里切出"用户报 bug → 出现失败信号 → 改文件修好"的 episode，把修复 diff 反推成可复跑的 pytest 骨架，让一次修复固化为测试。纯本地解析，不需要模型、不需要提交历史——修改前内容就在日志里（old_string / originalFile / apply_patch）。**

| 2026-10-17 | **弃"自动修复 / 自动改源码"** | 工具定位是"把已发生的修复钉成测试"，不是再当一个 agent。写源码会引入正确性责任与安全风险，且与 RED 验证的隔离原则冲突 → **只写测试目录 + 临时副本** |
| 2026-10-17 | **弃"用真实日志做基准"** | 真实日志含用户代码与 prompt，入库即破隐私红线；且只有 5 个严格样本，不足支撑统计。→ **基准一律合成会话 + 程序化植入真值**；真实样本只本地演示、人工抽验 |
| 2026-10-17 | **弃"AI 给 episode 打分"** | 打分用于过滤噪声，必须是可解释、可复现的规则（失败信号 +2 / diff +3 / 测试命令 +2 / 非文档改动 +2，阈值一处定义）；模型打分不可复现，也会让误切原因无法定位 |
| 2026-10-17 | 交付形态 | **纯本地 Python CLI**（唯一形态，无 GUI、无 exe 承诺）；`pip install .` 后 `python -m` / console_scripts 调用；退出码三语义 + 依赖缺失语义锁进测试 |
| 2026-10-17 | 数值口径 | episode 权重、阈值、验证超时、临时目录策略**只在 `config/scoring.toml` 一处定义**；报告 / 基准 / README 一律引用；题面 §2 的权重仅为口径声明 |

## 六、开工前预检结论（对应出题技能验收门）

- **素材可用性**：本题不以"版本化规则包"作亮点；底座是**会话日志内的修复前后内容**（✅ 本机实测 252/252 Edit 带 old/new、抽样 4/4 带 originalFile、104 次 apply_patch 可解析），非换标签充数。⬜ 三个字段语义待 M1 核对，题面已明确"未核对不得进入判定路径"。
- **数据底座可获取性**：双源本机实测 ✅；真实样本量小的局限已在题面 §1.3 与 §六 明写，评测主体为合成基准。
- **交付物可达性**：纯本地 Python CLI，零网络、零随包大文件；生成物只写目标仓库的测试目录
