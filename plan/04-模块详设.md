## 一、M0 已交付契约（骨架，测试锁死）

| 组件 | 接口 | 行为契约 | 守门 |
|---|---|---|---|
| `config.resolve_config_path(explicit, env, start)` | → `Path` | 四级顺序：`--config` → `S2R_CONFIG` → CWD 向上 6 层 `config/scoring.toml` → 随包副本；全不命中 → exit 2 + 提示 | 定位顺序测试 + 隔离目录（模拟装好的包）测试 |
| `config.load_config(path)` | → `dict` | 读 + 形状校验；缺键/类型错/越界/空词表**一次列全** | 逐项拒绝测试 |
| `config.weights / min_score / verify_params / generate_params / vocabulary / describe` | 类型化视图 | 全项目只经这些函数读口径值 | 配置叶子键集合 == `SCHEMA` 键集合 |
| `tomlmini.loads(text, origin)` | → `dict` | 支持子集：表头（含嵌套）、键值、字符串/整数/浮点/布尔、单行数组、内联表、跨行数组；**超集形态显式报错（带行号）** | 支持面测试 + 20 项拒绝面测试 |
| `serialize.dumps_json / write_json_atomic / write_text_atomic` | → `str` / `Path` | `sort_keys=True`、`ensure_ascii=False`、LF、结尾单换行、原子写 | 双跑/双写逐字节一致 + 无 CR + 无临时件残留 |
| `events.Event` | frozen dataclass | 字段集 `EVENT_FIELDS`；`seq` = 源行号 ≥1；`kind`/`source` 集外即报错；空串不是 `unknown` | IR 往返 + 哨兵 + seq 语义测试 |
| `events.detect_harness / detect_format_version` | → `str` | 按首行形态判别来源；未知 → `unsupported_format`（列出缺失键） | 已知两形态 + 未知 + 多命中测试 |
| `errors.*` | 异常层级 | 全部继承 `ValueError`（CLI 抓得住，不逃逸成 traceback）；携带 `code` 与 `exit_code` | CLI 契约测试逐码覆盖 |
| `stdio.ensure_utf8_stdio` | → None | 按流 `encoding` 探针决定是否 reconfigure；CJK 本地编码保持不动 | cp1252/cp936/StringIO 三形态测试 |
| `cli.main(argv)` | → `int` | 唯一入口；`--help`/`--version` 0；未知命令/缺参 2；`selftest` 0/1/3 | 全部子命令契约测试 |

### 1.1 CLI 命令面（**冻结**，M1–M5 只填实现不改形状）

| 命令 | 参数 | 交付 | 产物 |
|---|---|---|---|
| `s2r --version` | —— | M0 ✅ | 版本行 |
| `s2r selftest` | `--config` `--json` | M0 ✅ | 人读/机读自检结果 |
| `s2r config show\|path` | `--config` `--json` | M0 ✅ | 口径值 / 定位到的路径 |
| `s2r scan LOG...` | `--claude-root` `--codex-root` `--out` `--config` | M1 ✅ | 事件流 JSON（M2 起附 `episodes[]`） |
| `s2r bench` | `--only` `--data-dir` `--out` `--probe` `--check` `--config` | M1 ✅ | 基准报告 + 真值对账（双边门 + 探活） |
| `s2r reconstruct SESSION` | `--repo` `--out` `--config` | M3 | `files[*].before/after` |
| `s2r generate EPISODE_ID` | `--repo` `--out-dir` `--config` | M4 | `tests/regression/test_*.py` |
| `s2r verify EPISODE_ID` | `--repo` `--timeout` `--out-dir` `--config` | M5 | RED/GREEN 结论（退出码即结论） |
| `s2r run` | `--target`（必需） `--claude-root` `--codex-root` `--out-dir` `--config` | M5 | 全链路 + `regression/manifest.json` |

**中间产物全部落 `--out-dir`**（可单步复查，不用重跑整链）；`--timeout` 的默认值来自口径文件，
**代码内不留默认数值**。

### 1.2 "阶段未就绪"退出码（4）的退役流程

骨架期未实现的命令一律 `stage_not_ready` + exit 4，**绝不产出空结果**。某里程碑落地时，
**同一次提交**内四处同步：

1. `cli.STAGED_COMMANDS` 摘除该项（`registered_commands()` 仍含它）；
2. `tools/ci_smoke.py` 的 `EXPECTED_DEFAULT_ARGS` 改成真实调用形态 + 期望退出码；
3. README 退出码表删除"阶段未就绪"行（仅当全部命令都已交付——`tests/test_smoke_coverage.py` 会提醒）；
4. 本文件与 [06-里程碑.md](06-里程碑.md) 的状态列回写。
   少一处 = 幽灵语义复活（`errors.EXIT_STAGE_NOT_READY` 只在这四处被引用，`grep` 可核）。

## 二、M1：双 harness 读取器（统一事件流）

**输入**：Claude `~/.claude/projects/**/*.jsonl`、Codex `~/.codex/sessions/**/*.jsonl`（均可覆盖）。

**步骤**：
1. 发现日志根（`--claude-root`/`--codex-root` → 环境变量 → 常见位置探测；**不硬编码用户名**）；
   找不到显式报错（exit 2）。
2. 逐行读取（行长上限在口径文件）：空行跳过；非 JSON 行 → 显式报错并给出行号与截断片段。
3. **按首行形态**判别 harness（不按目录名：用户布局会漂，文件形态才是稳定事实）；未知 → `unsupported_format`。
4. 版本指纹检测（键集合显式）；不匹配 → 报错并列出缺失键。
5. 归一成 `Event`：`seq` = 源行号；`ts` 取日志字段、取不到落 `unknown`；
   文件类工具的 `path` 非空，其余落 `unknown`。
6. 会话聚合：`(source, session_id)` 排序输出 + 每条事件的来源行号/字节偏移。
7. `--out` 落盘（确定性写盘单点）。

**输出**：事件流 JSON `{schema_version, source_files[], sessions[], events[], notes[]}`。

**失败形态**：空目录 → exit 2；未知格式 → `unsupported_format`；超限 → 显式报错（不静默截断）。

**M1 必先闭环的三个 ⬜ 字段**（未闭环不得进入 M2 判定路径，K4）：

| # | 待核对项 | 闭环方式 | 结论落点 |
|---|---|---|---|
| R1 | Codex `apply_patch` 载荷内的**文件路径字段** | 全量逐样本核对键集与路径形态分布 | `data/README.md` §2.5 |
| R2 | Claude `MultiEdit` 的字段形态（本机是否出现） | 全量工具名聚合；未出现则登记"本机 0 次"并保留降级语义 | 同上 |
| R3 | Codex `exec` 的**失败判定字段语义** | 取成功/失败样本各若干逐字段对比 | 同上 |

**测试点**：合成日志逐字段对账；同一日志双跑逐字节一致；未知格式报错；超限报错；
**端到端双跑**（`scan` 输出 diff 为空——单元级确定性证明不了 CLI 出口的确定性）。

## 三、M2：Bug-fix episode 切分器（确定性规则，无模型）

**输入**：M1 事件流 + 语义词表（**唯一来源**：`config/scoring.toml` 的 `vocabulary`）。

**切分规则（按序、可回溯）**：
1. **起点**：`user_msg` 命中 bug/失败语义词；
2. **失败信号**：向后扫描命中 `tool_result` 的失败信号（信号集在配置文件）；
3. **修复动作**：失败信号之后出现文件写类工具（Claude `Edit`/`Write`、Codex patch 容器）；
4. **终点**：同一测试命令转为通过（`verified_by_run`）或会话结束（`ended_without_pass`）。

**输出**：`Episode{episode_id, session_id, source, start_ts, end_ts, user_report, failure_evidence[], edits[], test_commands[], score, status}`；
`episode_id` 由口径文件的 `id_format` 生成（会话 id + 首次修复事件序号，无时钟）。

**打分**：权重与阈值**只读**口径文件；打分是确定性规则（不是 AI 评分）。低于阈值的候选丢弃并计入统计。

**边界情形（每类必须有断言）**：一会话多 bug（各成独立 episode，`episode_id` 不撞）；
先成功后失败；失败后未修复（不出 episode 或按规则落 `ended_without_pass`）；
**用户仅提问**（不得被切为修复 episode）。同一输入 → 同一 episode 集合与同一排序。

**测试点**：合成基准真值逐例对账（应切/不应切都算，含上面四类边界）；
打分权重变更必须同步改测试；词表不内嵌（同文件出现多个词表词即红）。

## 四、M3：差分还原器（before/after 重建，不依赖 git）

**还原优先级（逐级降级，每级标 `source` 与 `confidence`）**：
1. `toolUseResult.type == "update"` 的 `structuredPatch` + `originalFile`（before 为全文，最可靠）；
2. `old_string`/`new_string` 在 `originalFile`／磁盘文件／同会话 `Write.content` 上定位替换；
3. Codex `apply_patch` 文本（`*** Begin Patch`/`*** Update File:`/`@@` 上下文）结合磁盘或上下文行重建；
4. 均不可得 → 该文件**不进生成路径**，episode 记 `unverified: no_before_image`。

**纪律**：多处命中且无法唯一定位 → `unresolved`（**不得任选一处**）；只能重建片段 → `partial`；
**绝不伪造上下文行**；同一日志 + 同一磁盘状态 → 同一 diff；不做 git 操作。

**输出**：`Reconstruction{file, before, after, hunks[], source, confidence}`（多文件 → 列表，逐文件独立置信度）。

**测试点**：合成基准 before/after **逐字符**对账；三条降级路径各有样例；`unresolved` 样例；
磁盘文件已被改动导致无法对齐时如实降级；双跑一致。

## 五、M4：pytest 骨架生成器（模板 + AST，不调模型）

**约定探测**：`tests/` 布局、`pytest.ini`/`pyproject.toml [tool.pytest.ini_options]`/`setup.cfg`/`tox.ini`、
`conftest.py` 与 fixture 风格、包根与 import 形态；**探测失败 → 保守默认 + manifest 标 `assumed_convention`
（默认值与占位文本均取自口径文件的 `[generate]`）**。

**输出** `tests/regression/test_<slug>.py`，结构固定：
* **docstring**：会话 id、事件时间戳、**原始用户报告原文**、失败信号摘录、修复文件清单（证据锚点可回溯）；
* **Arrange**：AST 读修改前签名 + diff 推断最小输入；无法构造 → 占位注释 + 标 `needs_manual`；
* **Act**：调用被改动的符号（diff 中被改动的函数/类优先）；
* **Assert**：占位 + 从 diff 推断的候选断言（返回值变化/异常类型变化/输出字符串变化），
  **必须注明"候选，需人工确认"**。

**纪律**：纯模板 + AST，零模型；同一 episode → **逐字节相同**骨架（稳定排序、稳定 slug）；
目标符号无法识别 → **不生成文件**（记 `needs_manual`）；**只写测试目录，不修改任何源码**（K11）。

**测试点**：合成基准生成内容对账（docstring 锚点齐全、AAA 三段在场）；同 episode 双跑逐字节一致；
`needs_manual` 有明确原因；变异验证"改一段 diff 描述 → 生成的候选断言随之变化"（防模板空转）。

## 六、M5：RED 验证器 + manifest（不验证不落盘）

**流程（隔离临时副本，不碰用户工作区）**：
1. 目标仓库复制到临时目录（前缀取口径文件 `tmpdir_prefix`）；
2. 写入 `before` 内容 → 运行新测试 → **必须失败（RED）**；
3. 切到 `after` 内容 → 运行同一测试 → **必须通过（GREEN）**；
4. 任一步不满足 → `unverified` + 原因（测试未失败 / 修复后仍失败 / 环境不可用 / 超时），
   **不写入正式测试目录**。

**输出** `regression/manifest.json`：每条 `episode_id`、`session_id`、`source`、文件与 hunk 摘要、
生成测试路径、RED/GREEN 退出码与**截断**日志摘要、`status ∈ {verified, unverified, needs_manual}`、
`reason`、生成器版本与生成时间；**覆盖度门槛（`coverage.min_count_by_type`）由基准 manifest 下发**。

**退出码**：`run`/`verify` = 0（至少一条 verified）/ 1（无 verified）/ 2（用法错误）/ 3（缺 pytest）。

**纪律**：验证在隔离目录进行；**不修改用户源码、不写用户 git 索引**；超时与临时目录策略一处定义；
RED/GREEN 结论同环境可重复。

**测试点**：before 必失败 / after 必通过的双跑；四类 `unverified` 原因各一条；
未通过项不进正式目录（断言目录内容）；退出码四语义各有测试；缺 pytest → exit 3（用 import 桩复现）。

## 七、跨模块统一纪律（每个里程碑收尾都要复跑）

1. **数据先行**：未核对的字段/形态不得进入判定或生成路径；核对结论先落 `data/README.md`。
2. **确定性**：无时钟、无随机、无网络、无并发；同输入双跑逐字节一致（中间层与 CLI 出口**两层**都断言）。
3. **判定不虚高**：第三态（`unknown`/`unresolved`/`unverified`/`needs_manual`）显式可见，不得折叠成"通过"。
4. **好门要证伪**：新增/改写的守门做一次变异验证（故意弄坏 → 必红）；弄不红 = 假门，当场重写判据。
5. **每条已交付命令**都要有 bare + module 两种形态的离线冒烟，并同步退役它的旧退出码断言。
6. **文档-实物一致**：README 的命令/extras/退出码/许可逐条有实物，靠测试而非人眼保证。
