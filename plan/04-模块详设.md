### 1.1 CLI 命令面（**冻结**，M1–M5 只填实现不改形状）

## 二、M1：双 harness 读取器（统一事件流）

**输入**：Claude `~/.claude/projects/**/*.jsonl`、Codex `~/.codex/sessions/**/*.jsonl`（均可覆盖）。

**步骤**：
1. 发现日志根（`--claude-root`/`--codex-root` → 环境变量 → 常见位置探测；**不硬编码用户名**）；
   找不到显式报错（exit 2）。
2. 逐行读取（行长上限在口径文件）：空行跳过；非 JSON 行 → 显式报错并给出行号与截断片段。
3. **按首行形态**判别 harness（不按目录名：用户布局会漂，文件形态才是稳定事实）；未知 → `unsupported_format`。
4. 版本指纹检测（键集合显式）；不匹配 → 报错并列出缺失键。
5. 归一成 `Event`：`seq` = 源行号；`ts` 取日志字段、取不到落 `unknown`；
   文件类工具的 `path` 非空，其余落 `unknown`。
6. 会话聚合：`(source, session_id)` 排序输出 + 每条事件的来源行号/字节偏移。
7. `--out` 落盘（确定性写盘单点）。

**输出**：事件流 JSON `{schema_version, source_files[], sessions[], events[], notes[]}`。

**失败形态**：空目录 → exit 2；未知格式 → `unsupported_format`；超限 → 显式报错（不静默截断）。

**M1 必先闭环的三个 ⬜ 字段**（未闭环不得进入 M2 判定路径，K4）：

| # | 待核对项 | 闭环方式 | 结论落点 |
|---|---|---|---|
| R1 | Codex `apply_patch` 载荷内的**文件路径字段** | 全量逐样本核对键集与路径形态分布 | `data/README.md` §2.5 |
| R2 | Claude `MultiEdit` 的字段形态（本机是否出现） | 全量工具名聚合；未出现则登记"本机 0 次"并保留降级语义 | 同上 |
| R3 | Codex `exec` 的**失败判定字段语义** | 取成功/失败样本各若干逐字段对比 | 同上 |

**测试点**：合成日志逐字段对账；同一日志双跑逐字节一致；未知格式报错；超限报错；
**端到端双跑**（`scan` 输出 diff 为空——单元级确定性证明不了 CLI 出口的确定性）。

## 三、M2：Bug-fix episode 切分器（确定性规则，无模型）

**输入**：M1 事件流 + 语义词表（**唯一来源**：`config/scoring.toml` 的 `vocabulary`）。

**切分规则（按序、可回溯）**：
1. **起点**：`user_msg` 命中 bug/失败语义词；
2. **失败信号**：向后扫描命中 `tool_result` 的失败信号（信号集在配置文件）；
3. **修复动作**：失败信号之后出现文件写类工具（Claude `Edit`/`Write`、Codex patch 容器）；
4. **终点**：同一测试命令转为通过（`verified_by_run`）或会话结束（`ended_without_pass`）。

**输出**：`Episode{episode_id, session_id, source, start_ts, end_ts, user_report, failure_evidence[], edits[], test_commands[], score, status}`；
`episode_id` 由口径文件的 `id_format` 生成（会话 id + 首次修复事件序号，无时钟）。

**打分**：权重与阈值**只读**口径文件；打分是确定性规则（不是 AI 评分）。低于阈值的候选丢弃并计入统计。

**边界情形（每类必须有断言）**：一会话多 bug（各成独立 episode，`episode_id` 不撞）；
先成功后失败；失败后未修复（不出 episode 或按规则落 `ended_without_pass`）；
**用户仅提问**（不得被切为修复 episode）。同一输入 → 同一 episode 集合与同一排序。

**测试点**：合成基准真值逐例对账（应切/不应切都算，含上面四类边界）；
打分权重变更必须同步改测试；词表不内嵌（同文件出现多个词表词即红）。

## 四、M3：差分还原器（before/after 重建，不依赖 git）✅ 2026-10-17

**还原优先级（逐级降级，每级标 `source` 与 `confidence`）**：

1. Claude `originalFile`（修改前全文）+ **非空** `structuredPatch`（有 hunk）——判据"键存在**且非空**"（K14：
   空表不含 diff，实测新建文件就带空表）；hunk 先按 `oldStart` 对行号，对不上再按内容唯一定位；
2. Claude `old_string`/`new_string` 在 before 基线上定位替换——基线按
   `originalFile` → 磁盘（**仅显式 `--repo`**）→ 同会话更早的 `Write.content` 取第一个可用者；
3. Codex：首选 `FileChange.changes[*].unified_diff`（结构化、带路径、带行号），
   `*** Begin Patch` 文本解析**降为兜底**（同文件两条通道都在时结构化通道胜出，另一条记进 `evidence.channels`）；
4. 都不可得 → 该文件**不进生成路径**，episode 记 `unverified: no_before_image`（新建文件的 `after`
   仍取自日志 `Write.content` / `Add File` 正文——那是事实，不因缺 before 就丢掉）。

**纪律（逐条有测试）**：多处命中且无法唯一定位 → `unresolved`（**不得任选一处**；`replace_all` 时全替换）；
只能重建片段 → `partial`（`before`/`after` 为 null，**绝不伪造上下文行**）；同一日志 + 同一磁盘状态 → 同一 diff；
不做 git 操作；磁盘只读且是**显式开关**（不给 `--repo` 就不碰工作区）。

**置信度口径**（由 before 镜像的**来源**决定，不由结果好坏决定）：
日志内全文 = `high`、磁盘工作区 = `medium`、只有片段 = `low`、取不到 = `none`。

**输出**：`Reconstruction{file, before, after, hunks[], source, confidence, status, reason, seq, evidence}`
（多文件 → 列表，逐文件独立置信度）+ 逐 episode 的 `{episode_id, status, reason, files[]}`；
`--out` 落盘走 `serialize` 单点（LF + 排序键，双跑逐字节一致）。

**实现落点**：`src/s2r/reconstruct.py`；CLI 在 `cli.cmd_reconstruct`（退出码 0/1/2 见 README 退出码表）。

**测试点**：合成基准 before/after **逐字符**对账（`bench` 的 `reconstructions` 事实面，逐文件逐字段点名）；
三条降级路径各有**具名样本**（`structured-patch-1` / `multi-bug-1` / `happy-path-1` / `ended-without-pass-1`）；
`unresolved`（`ambiguous-old-string-1`）与 `no_before_image`（`new-file-write-1`）各有样本；
磁盘对不上时如实降级（`base-drift-1`）；双跑一致（单元 + CLI 出口两层）。

## 五、M4：pytest 骨架生成器（模板 + AST，不调模型）

**约定探测**：`tests/` 布局、`pytest.ini`/`pyproject.toml [tool.pytest.ini_options]`/`setup.cfg`/`tox.ini`、
`conftest.py` 与 fixture 风格、包根与 import 形态；**探测失败 → 保守默认 + manifest 标 `assumed_convention`
（默认值与占位文本均取自口径文件的 `[generate]`）**。

**输出** `tests/regression/test_<slug>.py`，结构固定：
* **docstring**：会话 id、事件时间戳、**原始用户报告原文**、失败信号摘录、修复文件清单（证据锚点可回溯）；
* **Arrange**：AST 读修改前签名 + diff 推断最小输入；无法构造 → 占位注释 + 标 `needs_manual`；
* **Act**：调用被改动的符号（diff 中被改动的函数/类优先）；
* **Assert**：占位 + 从 diff 推断的候选断言（返回值变化/异常类型变化/输出字符串变化），
  **必须注明"候选，需人工确认"**。

**纪律**：纯模板 + AST，零模型；同一 episode → **逐字节相同**骨架（稳定排序、稳定 slug）；
目标符号无法识别 → **不生成文件**（记 `needs_manual`）；**只写测试目录，不修改任何源码**（K11）。

**测试点**：合成基准生成内容对账（docstring 锚点齐全、AAA 三段在场）；同 episode 双跑逐字节一致；
`needs_manual` 有明确原因；变异验证"改一段 diff 描述 → 生成的候选断言随之变化"（防模板空转）。

### 5.1 M4 已交付口径（实现决定，落档供下一棒与复核）

| # | 决定 | 理由 / 证据 |
|---|---|---|
| 1 | **只有 `ok` 进生成路径**；`partial` / `unresolved` / `no_before_image` 一律只记原因不产文件 | 没有修改前**全文**就读不出"修改前的签名"（AST 需要完整源码）；原因码 `reconstruction_not_usable:<状态>` |
| 2 | 非 `.py` 的改动单独记 `not_python`，与"`.py` 但解析不了"（`before_unparsable`）分开 | 真实会话抽验：`before_unparsable` 的**全部**来源是 `.md`/`.css` 一类文件；首期只生成 Python 测试 |
| 3 | **候选断言只认一种形态**：`return <expr> if <cond> else <alt>`，`cond` 恰为被调符号形参名、`alt` 为字面量；探测值取"与 `alt` 同型的假值" | 这是唯一能**保证**可证伪的形态：假值把守卫弄假 → 修复前抛错（红）、修复后返回 `alt`（绿）。已在隔离目录端到端核对（`test_generated_candidate_is_red_before_and_green_after`） |
| 4 | 推不出候选断言 → **仍然产出骨架**（三段 + 锚点），但标 `needs_manual` + `assert_not_derivable`；**写不出最小调用** → `probe_not_derivable`（占位） | "无法构造 Arrange → 占位注释 + needs_manual" 与"目标符号识别不到 → 不生成文件"是两条不同纪律 |
| 5 | 改动行定位用"旧侧文本在 before 里**唯一**出现"（不直接信 hunk 行号，也不任选） | 实测两种通道给的 `old_lines` 形态不同（整行 vs 不带缩进的片段），行号也可能为 null；不唯一即 `changed_lines_unknown` |
| 6 | 逐 episode 各自结论（会话内多修复互不牵连），slug = episode_id 规范化 | 稳定、文件系统安全、可复现；`sess-demo-0003#4` → `test_sess_demo_0003_4.py` |
| 7 | 落点显式：`--repo` 或 `--out-dir`，都不给 → exit 2；`--out-dir` 是**输出根**（目录形态与目标仓库一致） | 生成物只许落测试目录（K11）；绝不猜"要不要写进当前目录" |
| 8 | stdout = 机读产物（含骨架全文与逐 episode 结论），stderr = 人读摘要 | 与 `scan`/`reconstruct` 的"stdout 即产物"一致，同时给人读回执 |

**生成层对账面**（真值 `expect_generated` 由构造侧声明）：`generated_count` / `written_count` /
`statuses` / `reasons` / `symbols` / `candidate_count` / `sections` / `assumed_convention` /
`anchor_fragments`（**声明过的**必需锚点是否真的出现在骨架里）；差异点名到 `generated.<键>`。

## 六、M5：RED 验证器 + manifest（不验证不落盘）✅ 2026-10-17

**流程（隔离临时副本，不碰用户工作区）**：
1. 目标仓库复制到临时目录（前缀取口径文件 `tmpdir_prefix`；版本库与缓存目录不复制）；
2. 写入 `before` 内容 → 运行新测试 → **必须失败（RED）**；
3. 切到 `after` 内容 → 运行同一测试 → **必须通过（GREEN）**；
4. 任一步不满足 → `unverified` + 原因（测试未失败 / 修复后仍失败 / 环境不可用 / 超时），
   **不写入正式测试目录**。

**输出** `regression/manifest.json`：每条 `episode_id`、`session_id`、`source`、文件与 hunk 摘要、
生成测试路径、RED/GREEN 退出码与**截断**日志摘要、`status ∈ {verified, unverified, needs_manual}`、
`reason`、生成器版本与生成时间；**覆盖度门槛（`coverage.min_count_by_type`）由基准 manifest 下发**。

**退出码**：`run`/`verify` = 0（至少一条 verified）/ 1（无 verified）/ 2（用法错误）/ 3（缺 pytest）。

**纪律**：验证在隔离目录进行；**不修改用户源码、不写用户 git 索引**；超时与临时目录策略一处定义；
RED/GREEN 结论同环境可重复。

**测试点**：before 必失败 / after 必通过的双跑；四类 `unverified` 原因各一条；
未通过项不进正式目录（断言目录内容）；退出码四语义各有测试；缺 pytest → exit 3（用 import 桩复现）。

### 6.1 M5 已交付口径（实现决定，落档供下一棒与复核）

| # | 决定 | 理由 / 证据 |
|---|---|---|
| 1 | **可验证集 = 生成层产出了内容的 episode**；没内容 → `needs_manual` + 生成层原因码，两次退出码 `None`；有内容但无活动断言 → 照样跑两次 → `unverified` + `red_not_failed` | "测试没失败"与"测试通过了"是两件事：没有断言时两次跑都不失败，把它当 verified 是最容易发生的自欺（语料 `happy-path-1` / `multi-bug-1#9` 锁住） |
| 2 | **只有 `verified` 写进目标仓库测试目录**（`unverified` / `needs_manual` 只进 manifest） | "不验证不落盘"；与 `generate`（生成候选给人确认，`needs_manual` 也落）是两条不同的落点纪律，各自写进测试 |
| 3 | 路径映射只认**目标仓库里真的存在**的文件（`generate.relative_under_root` 一份实现两处用） | 映射不出来就硬写 = 往用户仓库新建文件/目录（K11 红线）；此时如实记 `environment_unavailable` |
| 4 | 判定**只看退出码**：`0` = 通过、`1` = 有测试失败，其余码算环境/用法问题 | 输出文本会随 pytest 版本漂；退出码语义稳定且可复现（也挡住"RED 判据恒真"这种退化） |
| 5 | 日志摘录只保留 `E`/`FAILED`/`ERROR` 前缀的行 | pytest 头部含平台/版本/耗时/临时目录，直接摘录会让 manifest 每次不同——摘录也要能进台账 |
| 6 | 生成时间取**会话日志的 `end_ts`**，不用时钟，也不加 `--generated-at` | 全链路禁时钟（K5）；CLI 命令面冻结（K12），不为一个可复算的字段加参数（同输入双跑 manifest 逐字节一致，有测试） |
| 7 | 口径文件里 `pytest_command` 用 `{python}` 占位，运行期换成 `sys.executable` | 装机后裸 `python` 未必在 PATH 上（本机实测 Windows 的 App Execution Alias 直接返回非 0），照抄会把"环境缺件"伪装成"测试没失败" |
| 8 | 冒烟新增 `%TMP_SEED:<相对目录>%` 占位符（现开临时目录 + 复制种子目录进去当目标仓库） | 验证需要"有源文件的目标仓库"，而生成物不许落进本仓库——一个占位符同时满足（K11 与冒烟可跑性） |
| 9 | manifest 的条目**不含骨架源码**（源码在 `test_path` 指的文件里） | manifest 是证据链，不是产物副本：复制一份源码会让"哪份是对的"变成两个事实 |

**验证层对账面**（真值 `expect_red_green` 由构造侧声明）：逐 episode 的 `episode_id` / `status` /
`reason` / **`red_exit` / `green_exit`**（两个退出码也进真值：它是"两次跑真的发生了"的硬证据）；
差异点名到 `red_green[<episode>].<键>`。

## 七、跨模块统一纪律（每个里程碑收尾都要复跑）

1. **数据先行**：未核对的字段/形态不得进入判定或生成路径；核对结论先落 `data/README.md`。
2. **确定性**：无时钟、无随机、无网络、无并发；同输入双跑逐字节一致（中间层与 CLI 出口**两层**都断言）。
3. **判定不虚高**：第三态（`unknown`/`unresolved`/`unverified`/`needs_manual`）显式可见，不得折叠成"通过"。
4. **好门要证伪**：新增/改写的守门做一次变异验证（故意弄坏 → 必红）；弄不红 = 假门，当场重写判据。
5. **每条已交付命令**都要有 bare + module 两种形态的离线冒烟，并同步退役它的旧退出码断言。
6. **文档-实物一致**：README 的命令/extras/退出码/许可逐条有实物，靠测试而非人眼保证。
