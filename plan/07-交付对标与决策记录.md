## 四、M0 决策记录（日期 + 结论 + 理由）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-17 | 计划先行 + 骨架先行，不直接进 M1 | 用户明确要求"先写好计划、部署骨架、不着急直接开始"；且骨架期落地横切契约成本最低（越早锁退出码/口径/写盘，后面越不会返工） |
| 2026-10-17 | 包与命令命名 | 发行名 `session-to-regression`，导入名 `s2r`，console script `s2r`；仓库名 `session-to-regression`，本地目录保留日期标签 |
| 2026-10-17 | 退出码新增 4 = 阶段未就绪 | 题面 0/1/2/3 已被占用（3 = 依赖缺失）；骨架期需要一个"未交付且不产结果"的显式语义，且必须**可退役**（四处同步流程见 [04](04-模块详设.md) §1.2） |
| 2026-10-17 | `selftest` 依赖缺失（pytest）单独判 3 | 自检失败（1）与依赖缺失（3）是两种语义；先判自检再判依赖，避免依赖缺失被自身 FAIL 行吞成 1 |
| 2026-10-17 | `--config` 只挂在叶子命令 | argparse 的子解析器默认值会覆盖父解析器已解析的值，挂两层会埋"传了但被默认值覆盖"的静默坑 |
| 2026-10-17 | 事件流 IR 的 `seq` = **源文件行号** | 行号可由日志独立复算；紧凑数组下标会随解析过滤漂移，破坏"同输入同一排序"的可复算性 |
| 2026-10-17 | M0 不宣称任何日志版本指纹 | R1–R3 未闭环；空指纹表的语义是**显式报错**而非"宽松解析"——宁可拒绝，不可静默错解 |
| 2026-10-17 | 三处 EOL/文件遍历规则收敛为单点实现 | `tools/fix_eol.py` 的"哪些文件算仓库文本"被测试与 CI 共用；两处各写一份必然漂移（一边排除构建元数据、另一边没排除 → 一半真一半假） |
| 2026-10-17 | M1：读取器按 `payload.type` 分流（不按顶层行类型/目录名） | Codex 的同一逻辑通道可出现在不同顶层行类型下；按内容形态分流才对真实布局鲁棒 |
| 2026-10-17 | M1：事件流**不复制大文本** | `originalFile`/`structuredPatch`/patch 全文只留引用（`seq` + `source_offset`），M3 用 `read_source_line` 取回原文——避免截断毁掉 before 镜像 |
| 2026-10-17 | M1：`FileChange` 作为结果侧事件纳入事件流（`tool=file_change`） | 它是 Codex 侧唯一带**结构化 diff** 的通道；**不承诺**与 `apply_patch` 配对（无 call_id，按时间序配对属猜测） |
| 2026-10-17 | M1：基准语料放 `data/bench/`，非法样本单列 `invalid/` | 混在 claude//codex/ 下会让「扫一个目录」这种正常用法必然失败（实测踩到） |
| 2026-10-17 | M1：基准门作用域分工 | 完整性门（台账/在位/覆盖度）看**全量语料**，判定门（检出率/误报）看 `--only` 选中的样本——缩小完整性门的扫描面等于让门漏检 |
| 2026-10-17 | M1：`s2r bench --probe` 的退出码取反 | 探活模式下 0 = 缺陷被检出、1 = 基准失灵；让「基准自己坏了」成为可见事件 |
| 2026-10-17 | 词表禁止在源码/测试/注释里复述词面 | 词表唯一来源是配置文件；举例子也算第二份词面（**首版注释里写了真实例子，门当场把自己的文档扫红**） |

## 六、与系列其他项目的关系（品牌隔离）

* 本仓库不与同系列其他项目共享代码，也不复用它们的业务领域词汇；
* 公开文档（README / Release notes / 技术报告）只描述"会话 → 回归测试"这一件事，
  不提及任何其他项目的名称与领域；
* 判据：**"这段话能让读者推出别的项目做什么吗？"** 能 → 改写。
