## 四、M0 决策记录（日期 + 结论 + 理由）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-17 | 计划先行 + 骨架先行，不直接进 M1 | 用户明确要求"先写好计划、部署骨架、不着急直接开始"；且骨架期落地横切契约成本最低（越早锁退出码/口径/写盘，后面越不会返工） |
| 2026-10-17 | 包与命令命名 | 发行名 `session-to-regression`，导入名 `s2r`，console script `s2r`；仓库名 `session-to-regression`，本地目录保留日期标签 |
| 2026-10-17 | 退出码新增 4 = 阶段未就绪 | 题面 0/1/2/3 已被占用（3 = 依赖缺失）；骨架期需要一个"未交付且不产结果"的显式语义，且必须**可退役**（四处同步流程见 [04](04-模块详设.md) §1.2） |
| 2026-10-17 | `selftest` 依赖缺失（pytest）单独判 3 | 自检失败（1）与依赖缺失（3）是两种语义；先判自检再判依赖，避免依赖缺失被自身 FAIL 行吞成 1 |
| 2026-10-17 | `--config` 只挂在叶子命令 | argparse 的子解析器默认值会覆盖父解析器已解析的值，挂两层会埋"传了但被默认值覆盖"的静默坑 |
| 2026-10-17 | 事件流 IR 的 `seq` = **源文件行号** | 行号可由日志独立复算；紧凑数组下标会随解析过滤漂移，破坏"同输入同一排序"的可复算性 |
| 2026-10-17 | M0 不宣称任何日志版本指纹 | R1–R3 未闭环；空指纹表的语义是**显式报错**而非"宽松解析"——宁可拒绝，不可静默错解 |
| 2026-10-17 | 三处 EOL/文件遍历规则收敛为单点实现 | `tools/fix_eol.py` 的"哪些文件算仓库文本"被测试与 CI 共用；两处各写一份必然漂移（一边排除构建元数据、另一边没排除 → 一半真一半假） |
| 2026-10-17 | M1：读取器按 `payload.type` 分流（不按顶层行类型/目录名） | Codex 的同一逻辑通道可出现在不同顶层行类型下；按内容形态分流才对真实布局鲁棒 |
| 2026-10-17 | M1：事件流**不复制大文本** | `originalFile`/`structuredPatch`/patch 全文只留引用（`seq` + `source_offset`），M3 用 `read_source_line` 取回原文——避免截断毁掉 before 镜像 |
| 2026-10-17 | M1：`FileChange` 作为结果侧事件纳入事件流（`tool=file_change`） | 它是 Codex 侧唯一带**结构化 diff** 的通道；**不承诺**与 `apply_patch` 配对（无 call_id，按时间序配对属猜测） |
| 2026-10-17 | M1：基准语料放 `data/bench/`，非法样本单列 `invalid/` | 混在 claude//codex/ 下会让「扫一个目录」这种正常用法必然失败（实测踩到） |
| 2026-10-17 | M1：基准门作用域分工 | 完整性门（台账/在位/覆盖度）看**全量语料**，判定门（检出率/误报）看 `--only` 选中的样本——缩小完整性门的扫描面等于让门漏检 |
| 2026-10-17 | M2：episode 层事实进基准对账面，`pending_facts` 只留未对账的面（M3–M5） | 「已对账」与「未对账」必须在报告里分得清：承诺了 episodes 就真比，没做到的才挂 pending |
| 2026-10-17 | M2：目录里的非会话 jsonl 单列 `not_a_session_log` | 它不是「格式漂移」（那是 `unsupported_format`），也不该静默跳过：真实目录里确实存在，静默吞掉会让「读了几个会话」变成猜 |
| 2026-10-17 | M2：单行上限 4 MiB → 16 MiB | 实测 Codex 单行可达 8.8 MB，原上限把 5/220 个真实会话排除在外（显式报出、未静默）；上限是安全阀不是规模判据 |
| 2026-10-17 | M2：`test_command_markers`/`test_pass_markers`/`doc_suffixes` 进口径文件 | 判定用得上的词面与后缀一律单点定义、代码零内嵌；标记另配「不得写成集合字面量」的判据 |
| 2026-10-17 | M1：`s2r bench --probe` 的退出码取反 | 探活模式下 0 = 缺陷被检出、1 = 基准失灵；让「基准自己坏了」成为可见事件 |
| 2026-10-17 | 词表禁止在源码/测试/注释里复述词面 | 词表唯一来源是配置文件；举例子也算第二份词面（**首版注释里写了真实例子，门当场把自己的文档扫红**） |
| 2026-10-17 | M3：`confidence` 由 before 镜像的**来源**决定（日志内全文 high / 磁盘 medium / 片段 low / 取不到 none） | 让置信度可解释、可复算；避免"结果看着对就标高置信度"的自由发挥 |
| 2026-10-17 | M3：磁盘对齐是**显式开关**（`--repo`），不给就不碰用户工作区 | 日志里写着某个绝对路径 ≠ 工具获准去读它；把"读工作区"变成一个用户可见的决定（隐私面 + 可测试） |
| 2026-10-17 | M3：`--repo` 语义 = "该编辑发生**前**的工作区状态"，工具不做时序推断 | 指到当前工作区（会话已应用）时 hunk 通常对不上 → 如实降级 `partial`；**不会把 after 当 before 交出去**（这正是 `base-drift-1` 样本锁住的坏路径） |

| 2026-10-17 | M3：语料真值增 `expect_reconstructions`，`pending_facts.before_after` 摘除 | "承诺了 before/after 对账"就必须真比：逐文件、逐字段点名（含来源与置信度），并把这条对账写进基准双边门 |
| 2026-10-17 | M3：基准语料新增两个**具名**降级样本并追加在 `SAMPLE_BUILDERS` 末尾 | 具名样本 = 每条降级路径都有"真的走到"的证据（M2 的教训：样本没走到 = 路径没验过）；追加在末尾让前面样本的 session id 与 RNG 抽样序列保持不变 |
| 2026-10-17 | M5：退出码 4 **整项退役**（常量、异常类、命令表、staged handler 一并删除） | 五条业务命令全部交付，"未交付"不再是可能的结论；留一个空表 + 死常量 = 幽灵语义（[04](04-模块详设.md) §1.2 的四处同步流程走完） |
| 2026-10-17 | M5：验证在**目标仓库的临时副本**里跑，源码由日志还原出的 before/after 覆盖 | 用户工作区零改动（连 pytest 缓存都留在副本里）；"在用户仓库里跑测试"会让一次验证变成一次不可逆的副作用（K11） |
| 2026-10-17 | M5：**只有 `verified` 落正式测试目录**；`needs_manual` 骨架照样跑两次并落 `unverified` + `red_not_failed` | "测试没失败"≠"测试通过了"：没有活动断言时两次跑都不失败，把它当通过是最容易发生的自欺；验证结论必须是**观测到的**，不是按生成层的标注推断的 |
| 2026-10-17 | M5：判定只看**退出码语义**（0 通过 / 1 有测试失败 / 其余算环境），不看输出文本 | 输出文本随 pytest 版本漂；退出码稳定、可复现，也挡住"RED 判据恒真"这类退化（变异 N11 专门打它） |
| 2026-10-17 | M5：生成时间取**会话日志的 `end_ts`**，不加 `--generated-at` 参数 | 全链路禁时钟（K5）：同输入双跑 manifest 必须逐字节一致；CLI 命令面冻结（K12），不为一个可复算的字段扩参数 |
