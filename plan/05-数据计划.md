# 05 数据计划（合成会话基准 + 植入真值 + 覆盖度门槛）

> 上游纪律全部来自 [data/README.md](../data/README.md)（§三 合成数据纪律、§四 数值口径纪律、§五 待核对项闭环表）。
> 本文件只写**计划**：生成什么、真值怎么定义、门槛怎么设、怎么防"基准自证"。

---

## 一、为什么基准一律合成

* 真实日志含**用户代码与 prompt**，入库即破隐私红线；
* 严格口径真实样本仅 5 个会话（宽松 29 个），**不足以支撑统计型结论**；
* 合成数据能**程序化植入真值**：生成时同步写出"应切出哪些 episode、before/after 是什么、
  生成测试应 RED→GREEN"，评测因此可零成本重复。

真实样本只作**演示与人工抽验**（本地、不入仓、不出现在公开仓库），样本数不作交付承诺。

---

## 二、生成物与生成器

| 项 | 位置 | 说明 |
|---|---|---|
| 生成器 | `tools/gen_bench.py` | 生成 Claude / Codex 两种格式的会话日志 + 同步写真值 |
| 冻结基准 | `data/bench/**` | 生成的合成日志（`.gitattributes` 标 `-text`：**字节即契约**，禁 EOL 归一） |
| 真值 | `data/bench/**/*.truth.json` | 与合成日志**同批生成**，不得事后人工补 |
| 覆盖度门槛 | `data/bench/manifest.json` → `coverage.min_count_by_type` | 门槛**随数据下发**（数据非代码） |
| 双跑守门 | `python tools/gen_bench.py --check` | 重生成到临时目录 → 与冻结物**逐字节**比对 |

**假值与白名单**：一律走 [data/README.md](../data/README.md) §三 登记的白名单（假项目名/假路径/
假 session id/假用户名）。**零真实项目、零真实路径、零真实用户名、零真实 session id。**

**确定性生成纪律**：禁止 stdlib `random` 序列（不承诺跨版本一致）→ 自研确定性 RNG（如 splitmix64）；
禁止 `set` 迭代序；禁止系统时钟（产物无时间戳）；生成器与真值入库、可用固定 seed 一条命令重建。

## 三、真值语义（"真值只存输入与期望，期望可由输入独立复算"）

真值文件**只允许**出现：输入侧（合成日志本身）+ 期望侧（应切 episode 的起止事件序号、
before/after 全文、期望 RED/GREEN 结论、应被过滤的低分候选）。

**明令禁止**的字段形态（出现即视为设计违规，守门测试会红）：

| 禁止形态 | 为什么 |
|---|---|
| `observed_*`（观测值） | 冻结"观测"会让基准退化成"比对两份预先算好的答案"——引擎全坏也全绿 |
| 由引擎实现算出的中间量 | 期望值与引擎同源 = 引擎自证（"把引擎注释掉，真值还能算出来吗？"算不出即违规） |
| 只声明"某类有值"而输入无法复算 | 期望值必须能由输入 + 规则**独立推导**（例：若所有调用间隔都落在窗口内，"窗口内重试"就对每个样本都成立，真值失去区分度） |

**判据**：把引擎实现删掉，真值仍能由合成日志 + 规则复算出来。

## 四、覆盖度门槛（防"合成真值偏科"）

基线必须按 episode 类型设最低条数，类型枚举与门槛口径在 `data/bench/manifest.json` 一处定义
（类型清单见 [data/README.md](../data/README.md) §三.3，含正常修复链、未观察到通过、
一会话多 bug、无失败信号、只改文档、多重命中、纯新建文件、未知格式等类型）。

**三条配套纪律**：

1. **逐样本点名**：差异必须落到具体样本 id，禁止用汇总率掩盖"某类全零"；
2. **双边门**：既守**误报率 0**（不该切的没切），也守**检出率 ≥ 门槛**（该切的都切到）——
   只守误报的门在引擎整体失效时照样全绿；
3. **错误类型归属逐样本核对**：只查"是否判错"会被"任意一类命中就算检出"蒙混。

## 五、可证伪探活（"基准全绿"本身不算证据）

* **探活** = 重跑同一套 check 并**必须报出差异**：注入一个已知缺陷（如把某类样本的失败信号抹掉）
  → 基准必须报未达标；探活注入值从**实算值**派生，不写死。
* **探活打在消费处**：断言落在"读真值并比对"的那一侧，而不是定义处。
* **守门函数必须有测试真调它**（零调用点 = 空转）。
* **冻结基准必须被"用户敲的那条命令"真读**（`s2r bench`），不是只在测试里被读。
* **真值未声明项记 `undeclared`**，不静默当通过。
* **"未启用"的套件不许冒充通过**：空分母分支要显式 `not_enabled` 并带原因（退出码与"跑了没过"可区分）。

## 六、基准指标与 README 披露口径

* 指标粒度**如实标注**：计数级 ≠ 逐条级；任何"准确率"都必须注明**分母来源**（合成基准？多少例？）。
* README 只展示能从基准复算的数（且数字以末态回填，不写会漂移的预期值）。
* 真实样本相关表述一律带"严格口径 5 / 宽松 29"的样本量声明，**不得包装成"大规模验证"**。

## 八、基准与真实样本的隔离

* `data/bench/**` 只含合成数据；真实日志永不入库（`.gitignore` 已屏蔽 `sessions/`、`exports/`、
  `**/_real_logs/`、`data/**/_private/`）。
* 演示用的真实样本只在本机跑，README 只描述**脱敏后的形态**（不写真实路径与完整 session id）。
* 生成物（`tests/regression/*.py`）默认只落本地；公开仓库只含**生成器与合成输入**，
  不含任何来自真实会话的代码片段。
