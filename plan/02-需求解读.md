## 一、痛点 → 能力转译

| # | 痛点（题面 §1.1，HN 原话已核对） | 本工具给出的能力 | 落在哪个模块 |
|---|---|---|---|
| 1 | agent「让测试变绿」并把**几周前的修复改回去** | 把每次真实修复**钉成回归测试**：修复后代码必须让该测试通过；若被改回去，测试立刻变红 | M3 → M4 → M5 |
| 2 | 修复完成即证据消失，除非固化成测试 | 从会话日志里把「失败 → 修复」这一对**原样取出**，产出可复跑的 pytest 文件与 manifest | M1 → M2 → M4 |
| 3 | 「先写失败测试」可以外包，但没人从**已发生**的修复反推 | 无需重放会话：修改前内容就在日志里（`structuredPatch`/`originalFile`/`old_string`/`apply_patch`） | M3 |
| 4 | 覆盖率停滞的根因是**流程断裂** | 交付物进既有工作流：文件写进目标仓库 `tests/regression/`，manifest 记录证据链，一条命令可重跑 | M4 → M5 → CLI |

**能力收敛成一句话**：**输入本机会话日志，输出"会红灯"的回归测试与可审计的证据清单**；
不联网、不调模型、不依赖 git、不修改用户源码。

## 二、用户旅程（含每一步的失败形态）

| 步 | 用户动作 | 工具行为 | 失败形态（必须显式，不得静默） |
|---|---|---|---|
| 1 | `s2r run --target <repo>` | 发现本机日志根 → 读取（M1） | 找不到日志根 → exit 2 并提示 `--claude-root/--codex-root`；**不伪造空结果** |
| 2 | —— | 切分 episode（M2） | 打分低于阈值 → 丢弃并计入统计（不是"零结果 exit 0"）；字段未核对 → 落 `unknown` 并注记 |
| 3 | —— | 还原 before/after（M3） | 无法唯一定位 → `unresolved`；只能重建片段 → `partial`；都不可得 → `unverified: no_before_image` |
| 4 | —— | 生成 pytest 骨架（M4） | 目标符号识别不到 → 不生成文件、记 `needs_manual`；约定探测失败 → 保守默认 + manifest 标 `assumed_convention` |
| 5 | —— | RED/GREEN 双验证（M5） | before 不失败 / after 仍失败 / 超时 / 环境不可用 → `unverified` + 原因，**不写正式测试目录** |
| 6 | 用户 review `manifest.json` | 逐条给出 episode 锚点、文件、hunk、退出码与日志摘要 | 未验证项不进正式目录；生成物不得混入未验证件 |
| 7 | 用户把验证过的测试提交进自己的仓库 | 工具**不做** git 操作、不改源码 | —— |
| 8 | （可选）真实样本人工抽验 | 本地跑、不落库 | 真实日志/路径/session id 一律不入仓 |

**关键体验约束**：命令要能被 CI/脚本消费（退出码语义固定）、产物要能被人读（docstring 带原始
用户报告与证据锚点）与机器读（manifest JSON 确定性字节）。

## 三、FR 功能清单（含优先级与验收判据）

> 优先级：**P0 = 首期必达**；**P1 = 首期应达（有降级路径）**；**P2 = 扩展项，不入首期**。

| FR | 内容 | 里程碑 | 优先级 | 验收判据（可执行） |
|---|---|---|---|---|
| FR-1 | 读 Claude Code 会话（`~/.claude/projects/**/*.jsonl`），路径自适应 + `--claude-root`/环境变量覆盖 | M1 | P0 | 合成日志逐字段对账；**不得硬编码用户名**；找不到源显式报错 |
| FR-2 | 读 Codex 会话（`~/.codex/sessions/**/*.jsonl`），路径同上 | M1 | P0 | 同上 |
| FR-3 | 归一事件流 IR（`Event`），按**首行形态**判别来源 | M1 | P0 | 未知形态 → `unsupported_format`（列出缺失键）；同一日志双跑逐字节一致 |
| FR-4 | 格式版本指纹检测 | M1 | P0 | 指纹表为空/不匹配 → 显式报错；**不猜测解析** |
| FR-5 | bug-fix episode 切分（确定性状态机：起点 → 失败信号 → 修复动作 → 终点） | M2 | P0 | 合成基准真值**逐例**对账（应切/不应切都算） |
| FR-6 | episode 打分与阈值过滤（权重与阈值只在 `config/scoring.toml`） | M2 | P0 | 权重变更必须同步改测试；低分候选计入过滤统计 |

| FR-8 | before/after 三级降级还原（structuredPatch → old_string/new_string → apply_patch） | M3 | P0 | 合成基准逐字符对账；多重命中 → `unresolved`，**不得任选一处** |
| FR-9 | 还原置信度与来源标注（`source` + `confidence`，逐文件独立） | M3 | P0 | 降级路径各有一条样例；越级降级必须降 confidence |
| FR-10 | 测试约定探测（`tests/` 布局、配置、conftest） | M4 | P1 | 探测失败 → 保守默认 + manifest 标 `assumed_convention` |
| FR-11 | pytest 骨架生成（docstring 证据锚点 + Arrange/Act/Assert + 候选断言） | M4 | P0 | 同 episode 逐字节稳定；候选断言必须标"需人工确认" |
| FR-12 | RED/GREEN 双验证（隔离临时副本） | M5 | P0 | before 必失败、after 必通过；任一步不满足 → `unverified` + 原因 |
| FR-13 | `regression/manifest.json` 证据链 | M5 | P0 | schema 测试 + `status`/`reason` 枚举约束 |
| FR-14 | CLI 退出码语义（0/1/2/3/4）锁进测试 | M0 起 | P0 | 未知命令 2、缺参数 2、缺依赖 3、阶段未就绪 4、无 verified 1 |
| FR-15 | 合成会话基准 + 程序化植入真值 | M1 | P0 | 生成器 `--check` 位级一致；覆盖度门槛写进 manifest |

## 四、验收口径（怎么算"做到了"）

1. **判定不虚高**：`unverified` / `unresolved` / `needs_manual` / `assumed_convention` 都是**独立可见**的
   第三态，绝不把"没验证出来"写成"验证通过"；未通过项**不进正式测试目录**。
2. **交付路径 == 验收路径**：评分与 DoD 全部打在 CLI 命令上（`scan`/`reconstruct`/`generate`/`verify`/`run`），
   不只打库函数；基准也从 CLI 入口跑（见 [00-README总览.md](00-README总览.md) §四 招牌动词表）。
3. **可证伪**：每条守门都要有一次"故意弄坏 → 必红"的变异验证记录；每条已交付命令都要有离线冒烟。
4. **不写会漂移的硬数字**：测试数/文件数/体积/通过率一律不写进文档；确需数字用末态回填。
5. **诚实口径**：未接远端期间一切 CI 类结论写"本地等价校验，未接远端，CI 待首推验证"；
   样本量局限在 README 与题面同时披露。

## 五、边界与非目标（转译题面 §六，逐条可查）

* **只固化已发生的修复**：不补覆盖率、不设计新功能测试。
* **不修改用户源码、不碰 git 索引**：只写测试目录与临时副本（FR-12 的隔离副本）。
* **不依赖 git**：git 仅可选加速；缺 git 全链路可跑。
* **不做 AI 评分、不调模型**：打分是确定性规则。
* **首期只生成 Python 测试**：`.mjs`/`.ts` 只识别。
* **隐私红线**：纯本地、零上传、零遥测；真实日志/路径/session id 不入仓。
* **样本量局限**：严格口径真实样本仅 5 个会话（宽松 29），评测主体是合成基准。
* **不承诺跨版本兼容**：不认识的新格式显式报错。
